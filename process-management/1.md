## 🎯 Why Limit Process Resources?

### Common Scenarios

| Scenario | Why Limit Resources? |
|----------|---------------------|
| **Runaway Processes** | Prevent a single process from consuming all CPU |
| **Memory Leaks** | Stop processes from exhausting system RAM |
| **Multi-tenant Environments** | Ensure fair resource distribution |
| **Development/Testing** | Simulate resource-constrained environments |
| **Cost Optimization** | Prevent resource over-provisioning |

### Benefits

✅ **System Stability** → Prevent crashes from resource exhaustion  
✅ **Fair Resource Distribution** → All processes get their share  
✅ **Predictable Performance** → No unexpected slowdowns  
✅ **Better Monitoring** → Easier to identify problematic processes

## 🐧 Linux Methods

### Method 1: Using `systemd-run` (Recommended for New Processes)

**Best for:** Starting new processes with resource limits

#### Basic Syntax

```bash
sudo systemd-run --scope -p CPUQuota=50% -p MemoryMax=500M your_command_here
```

#### Parameters Explained

| Parameter | Description | Example |
|-----------|-------------|---------|
| **`--scope`** | Creates a new scope unit | Always use with `systemd-run` |
| **`-p CPUQuota=50%`** | Limits CPU to 50% of one core | `100%` = 1 core, `200%` = 2 cores |
| **`-p MemoryMax=500M`** | Limits memory to 500MB | `1G`, `1024M`, `500M` |

#### Examples

```bash
# Limit a web server to 40% CPU and 1GB RAM
sudo systemd-run --scope -p CPUQuota=40% -p MemoryMax=1G nginx

# Limit a Python script to 20% CPU and 200MB RAM
sudo systemd-run --scope -p CPUQuota=20% -p MemoryMax=200M python3 myscript.py

# Limit a Java application to 60% CPU and 2GB RAM
sudo systemd-run --scope -p CPUQuota=60% -p MemoryMax=2G java -jar app.jar

# Limit a database to 80% CPU and 4GB RAM
sudo systemd-run --scope -p CPUQuota=80% -p MemoryMax=4G postgres
```

#### Verify Limits

```bash
# Check the process with systemd-cgtop
systemd-cgtop

# Check specific scope
systemctl show --property=CPUQuota,MemoryMax --value scope
```

### Method 2: Using `cpulimit` (CPU Only, Running Processes)

**Best for:** Limiting CPU on **already running** processes

#### Installation

```bash
# Ubuntu/Debian
sudo apt-get install cpulimit

# CentOS/RHEL
sudo yum install cpulimit

# Fedora
sudo dnf install cpulimit
```

#### Basic Syntax

```bash
sudo cpulimit --pid <PID> --limit <PERCENTAGE>
```

#### Examples

```bash
# Limit process with PID 1234 to 30% CPU
sudo cpulimit --pid 1234 --limit 30

# Limit process by program name to 50% CPU
sudo cpulimit --exec /path/to/program --limit 50

# Run cpulimit in background for a PID
sudo cpulimit --pid 1234 --limit 40 --background

# Verbose mode for monitoring
sudo cpulimit --pid 1234 --limit 25 --verbose
```

#### Find PID

```bash
# Find PID by process name
ps aux | grep process_name

# Find PID by port
sudo lsof -i :8080

# Find PID by program
pgrep -f "program_name"
```

#### Stop cpulimit

```bash
# Find cpulimit PID
ps aux | grep cpulimit

# Kill cpulimit
sudo kill <cpulimit_pid>
```

### Method 3: Using `prlimit` (Memory Only, Running Processes)

**Best for:** Limiting memory on **already running** processes

#### Basic Syntax

```bash
sudo prlimit --pid=<PID> --as=<BYTES>
```

#### Parameters Explained

| Parameter | Description | Example |
|-----------|-------------|---------|
| **`--pid`** | Process ID | `1234` |
| **`--as`** | Virtual memory address space limit | `524288000` (500MB in bytes) |
| **`--rss`** | Resident set size (physical memory) | `524288000` |

#### Examples

```bash
# Limit process 1234 to 500MB virtual memory
sudo prlimit --pid=1234 --as=524288000

# Limit process 1234 to 256MB physical memory
sudo prlimit --pid=1234 --rss=268435456

# Check current limits for a process
prlimit --pid=1234

# Set both CPU and memory limits (use with cpulimit)
sudo prlimit --pid=1234 --as=524288000
sudo cpulimit --pid 1234 --limit 30
```

#### Memory Size Conversion

| Memory | Bytes | prlimit Value |
|--------|-------|---------------|
| 100MB | 104,857,600 | 104857600 |
| 256MB | 268,435,456 | 268435456 |
| 500MB | 524,288,000 | 524288000 |
| 1GB | 1,073,741,824 | 1073741824 |
| 2GB | 2,147,483,648 | 2147483648 |

### Method 4: Using `cgroups` (Advanced)

**Best for:** Fine-grained control in production environments

#### Basic Setup

```bash
# Create a cgroup
sudo mkdir /sys/fs/cgroup/cpu/mygroup
sudo mkdir /sys/fs/cgroup/memory/mygroup

# Set CPU limit (50% of one core)
echo 50000 > /sys/fs/cgroup/cpu/mygroup/cpu.cfs_quota_us
echo 100000 > /sys/fs/cgroup/cpu/mygroup/cpu.cfs_period_us

# Set memory limit (500MB)
echo 524288000 > /sys/fs/cgroup/memory/mygroup/memory.limit_in_bytes

# Add process to cgroup
echo <PID> > /sys/fs/cgroup/cpu/mygroup/cgroup.procs
echo <PID> > /sys/fs/cgroup/memory/mygroup/cgroup.procs
```

#### Using `cgcreate` and `cgset` (Helper Tools)

```bash
# Install cgroup tools
sudo apt-get install cgroup-tools

# Create cgroup with limits
sudo cgcreate -g cpu,memory:mygroup
sudo cgset -r cpu.cfs_quota_us=50000 mygroup
sudo cgset -r memory.limit_in_bytes=524288000 mygroup

# Run command in cgroup
sudo cgexec -g cpu,memory:mygroup your_command

# Add running process to cgroup
sudo cgclassify -g cpu,memory:mygroup <PID>
```

### Method 5: Using `ulimit` (Shell Built-in)

**Best for:** Limiting shell sessions and child processes

#### Basic Syntax

```bash
ulimit -a              # Show all limits
ulimit -v <KB>         # Virtual memory limit
ulimit -t <SECONDS>    # CPU time limit
```

#### Examples

```bash
# Limit virtual memory to 500MB for current shell
ulimit -v 524288

# Limit CPU time to 60 seconds
ulimit -t 60

# Run a command with limits
(ulimit -v 524288 && your_command)
```

## 🪟 Windows Methods

### Method 1: Core Affinity (Built-in)

**Best for:** Limiting CPU cores used by a process

#### Steps

1. Open **Task Manager** (Ctrl+Shift+Esc)
2. Go to **Details** tab
3. Right-click the process
4. Click **Set Affinity**
5. Uncheck specific CPU cores
6. Click **OK**

#### Example

```
Process: java.exe
Affinity: Uncheck CPU 0 and CPU 1
Result: Process can only use CPU 2 and CPU 3
```

#### Using PowerShell (Programmatic)

```powershell
# Get process
$Process = Get-Process -Name "process_name"

# Set affinity to core 0 and 1 only
$Process.ProcessorAffinity = 0x3  # Binary: 11 (cores 0 and 1)

# Set affinity to core 0 only
$Process.ProcessorAffinity = 0x1  # Binary: 01 (core 0)

# Set affinity to cores 2 and 3
$Process.ProcessorAffinity = 0xC  # Binary: 1100 (cores 2 and 3)
```

#### Affinity Mask Reference

| Cores | Binary | Hex |
|-------|--------|-----|
| Core 0 | 0001 | 0x1 |
| Core 1 | 0010 | 0x2 |
| Cores 0-1 | 0011 | 0x3 |
| Core 2 | 0100 | 0x4 |
| Cores 0-2 | 0111 | 0x7 |
| Cores 0-3 | 1111 | 0xF |

### Method 2: Process Lasso (Third-party)

**Best for:** Granular resource control and automation

#### Features

- Set permanent CPU and memory limits
- Automatic process prioritization
- GUI and CLI interface
- Performance monitoring

#### Basic Usage

1. Download and install Process Lasso
2. Right-click the process
3. Select "CPU Limiter" → "Set CPU Limit"
4. Choose percentage limit
5. Click "Apply"

#### CLI Example

```bash
# Process Lasso command line
processlasso.exe setaffinity --pid=1234 --cores=0,1
processlasso.exe setpriority --pid=1234 --priority=belownormal
```

### Method 3: Windows Job Objects (Programming)

**Best for:** Developers and automated deployments

#### C++ Example

```cpp
// Create a job object
HANDLE hJob = CreateJobObject(NULL, NULL);

// Set limits
JOBOBJECT_EXTENDED_LIMIT_INFORMATION jeli = {};
jeli.BasicLimitInformation.LimitFlags = JOB_OBJECT_LIMIT_CPU_RATE_CONTROL |
                                          JOB_OBJECT_LIMIT_JOB_MEMORY;
jeli.CpuRateControl = 50;  // 50% CPU
jeli.JobMemoryLimit = 500 * 1024 * 1024;  // 500MB

SetInformationJobObject(hJob, JobObjectExtendedLimitInformation, &jeli, sizeof(jeli));

// Assign process
AssignProcessToJobObject(hJob, hProcess);
```

### Method 4: PowerShell (CPU Priority)

**Best for:** Quick CPU priority adjustments

```powershell
# Set process priority
Get-Process -Name "process_name" | ForEach-Object { $_.PriorityClass = "BelowNormal" }

# Available priorities:
# - Idle
# - BelowNormal
# - Normal
# - AboveNormal
# - High
# - RealTime

# Example: Set Chrome to BelowNormal
Get-Process -Name "chrome" | ForEach-Object { $_.PriorityClass = "BelowNormal" }
```

## 🚀 Quick Decision Guide

### Which Method to Use?

| Your Need | Linux | Windows |
|-----------|-------|---------|
| **New process with CPU+Memory limits** | `systemd-run` | Use startup parameters or Process Lasso |
| **Running process CPU limit** | `cpulimit` | Set affinity (reduces cores) |
| **Running process Memory limit** | `prlimit` | Process Lasso or Job Objects |
| **Simple CPU restriction** | `ulimit -t` | Set affinity (Task Manager) |
| **Advanced control** | `cgroups` | Process Lasso |

## 🛠️ Troubleshooting Common Issues

| Issue | Linux | Windows |
|-------|-------|---------|
| **"Permission denied"** | Use `sudo` | Run as Administrator |
| **Process not found** | Check PID: `ps aux \| grep process` | Check Task Manager or `Get-Process` |
| **Limits not applying** | `cpulimit` needs root | Affinity only limits cores, not usage |
| **CPU limit too strict** | Increase percentage | Add more cores to affinity |
| **Memory limit causing crashes** | Increase MemoryMax | Use Process Lasso to adjust |
| **Limits not persistent** | Use systemd service | Use Task Scheduler for startup |

### Linux Debugging Commands

```bash
# Check process status
ps aux | grep <process>

# Check systemd limits
systemctl show --property=CPUQuota,MemoryMax --value scope

# Check cpulimit is running
ps aux | grep cpulimit

# Check cgroup limits
cat /sys/fs/cgroup/cpu/mygroup/cpu.cfs_quota_us
cat /sys/fs/cgroup/memory/mygroup/memory.limit_in_bytes

# Check prlimit
prlimit --pid <PID>
```

### Windows Debugging Commands

```powershell
# Get process details
Get-Process -Name "process_name"

# Get CPU affinity
$Process = Get-Process -Name "process_name"
$Process.ProcessorAffinity

# Get priority
$Process.PriorityClass

# Get memory usage
Get-Process -Name "process_name" | Select-Object Name, WorkingSet, PeakWorkingSet
```

## 💡 Best Practices & Key Takeaways

### Best Practices

| Practice | Why |
|----------|-----|
| **Start with systemd-run for Linux** | Simple, built-in, reliable |
| **Use cpulimit for running processes** | No restart needed |
| **Set both CPU and memory limits** | Comprehensive control |
| **Monitor before limiting** | Understand baseline usage |
| **Test limits in staging** | Avoid production surprises |
| **Document your limits** | Team awareness |

### Key Takeaways

| Concept | Key Insight |
|---------|-------------|
| **systemd-run** | Best for new processes with CPU+Memory |
| **cpulimit** | Best for CPU on running processes |
| **prlimit** | Best for Memory on running processes |
| **Affinity** | Windows CPU core restriction |
| **Process Lasso** | Windows full resource control |

### When to Use Which Tool

| Tool | Best For |
|------|----------|
| **systemd-run** | Starting new services in production |
| **cpulimit** | Quick CPU limit on running process |
| **prlimit** | Quick memory limit on running process |
| **cgroups** | Advanced, production-grade control |
| **ulimit** | Shell sessions and simple limits |
| **Affinity** | Quick CPU core restriction (Windows) |
| **Process Lasso** | Comprehensive Windows control |
