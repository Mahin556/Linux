# 🔍 How to Identify the Port Used by a Service on Linux

This guide walks you through the process of identifying which port a specific service (named `app`) is using on a Linux server. You'll learn multiple approaches using common networking tools.

---

## 📚 Quick Summary of Tools

| Tool | Best For | Availability |
|------|----------|--------------|
| **`ss`** | Modern, fast, preferred | Most modern distros |
| **`netstat`** | Traditional, widely known | Most distros (may need installation) |
| **`lsof`** | File-based approach, detailed | Most distros |

---

## 🎯 Method 1: Using `ss` (Recommended)

The `ss` (socket statistics) tool is the modern replacement for `netstat`. It's faster and more efficient.

### Basic Command

```bash
ss -tulpn | grep app
```

### Parameter Breakdown

| Option | Description |
|--------|-------------|
| `-t` | Show TCP sockets |
| `-u` | Show UDP sockets |
| `-l` | Show only listening sockets |
| `-p` | Show process using the socket |
| `-n` | Show numeric ports (don't resolve service names) |

### Example Usage

```bash
# Find all listening ports and grep for "app"
ss -tulpn | grep app

# More specific: find listening TCP ports for app
ss -tlpn | grep app

# Find listening ports with process details
ss -tulnp | grep -i app
```

### Expected Output

```
tcp   LISTEN 0      128        0.0.0.0:8080      0.0.0.0:*    users:(("app",pid=1234,fd=5))
```

**Interpretation:**
- Port: `8080`
- Process: `app`
- PID: `1234`

## 🎯 Method 2: Using `netstat`

The classic tool, still widely available.

### Basic Command

```bash
netstat -tulpn | grep app
```

### Parameter Breakdown

| Option | Description |
|--------|-------------|
| `-t` | Show TCP sockets |
| `-u` | Show UDP sockets |
| `-l` | Show only listening sockets |
| `-p` | Show process using the socket |
| `-n` | Show numeric ports |

### Example Usage

```bash
# Standard command
netstat -tulpn | grep app

# Alternative format
netstat -tulnp | grep app

# If netstat is not available, install it
sudo apt install net-tools   # Debian/Ubuntu
sudo yum install net-tools   # RHEL/CentOS
```

### Expected Output

```
tcp        0      0 0.0.0.0:8080            0.0.0.0:*               LISTEN      1234/app
```

---

## 🎯 Method 3: Using `lsof`

`lsof` (List Open Files) can also identify network connections.

### Basic Command

```bash
lsof -i -P -n | grep app
```

### Parameter Breakdown

| Option | Description |
|--------|-------------|
| `-i` | Show network files (sockets) |
| `-P` | Show port numbers (not service names) |
| `-n` | Show IP addresses (not hostnames) |

### Example Usage

```bash
# Standard command
lsof -i -P -n | grep app

# Show listening ports only
lsof -i -P -n | grep LISTEN | grep app

# Show TCP ports only
lsof -iTCP -P -n | grep app
```

### Expected Output

```
app     1234  user    5u  IPv4  12345      0t0  TCP *:8080 (LISTEN)
```

**Interpretation:**
- Port: `8080`
- Process: `app`
- PID: `1234`
- State: `LISTEN`

## 🔍 Method 4: Finding Port Without Knowing the Name

If you're unsure about the exact process name, try these alternatives:

### Using Process Name Variations

```bash
# Try different name patterns
ss -tulpn | grep -i "app"
ss -tulpn | grep -E "app|application"

# Check all listening ports and their processes
ss -tulpn | grep LISTEN

# Check all listening ports with process info
sudo ss -tulpn
```

### Using PID First

```bash
# Find the PID of the app
pgrep -f app

# Then find the port using the PID
sudo ss -tulpn | grep <PID>
```

## 🚨 Common Pitfalls

### 1. Permission Denied

If you see `Permission denied` or missing process information, run with `sudo`:

```bash
sudo ss -tulpn | grep app
sudo netstat -tulpn | grep app
sudo lsof -i -P -n | grep app
```

### 2. `grep` Matches Multiple Lines

If `grep` returns too many results, refine your search:

```bash
# Search exact process name
ss -tulpn | grep -w "app"

# Search only TCP ports
ss -tlpn | grep app

# Search only UDP ports
ss -ulpn | grep app
```

### 3. No Results Found

If you get no results, the service might be:
- Not running
- Using a different name
- Not listening on any port

Check if the service is running:

```bash
systemctl status app
ps aux | grep app
```
