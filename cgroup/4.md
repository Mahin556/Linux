# 🧩 Understanding `system.slice` in systemd

`system.slice` is a fundamental concept in systemd that serves as a **container or "box" for organizing and limiting system services**. It's a type of systemd unit that ends with `.slice` and represents a hierarchical group of processes used for resource management with Linux cgroups.

---

## 🏠 What is `system.slice`?

Think of `system.slice` as the **default home** for all system-level services in a Linux system.

| Aspect | Description |
|--------|-------------|
| **Type** | Systemd slice unit (`.slice` file) |
| **Purpose** | Organize and manage system services hierarchically |
| **Default** | Created automatically by systemd |
| **Resource Control** | Can have CPU, memory, I/O limits applied |

---

## 📊 The cgroup Hierarchy

In a systemd-based Linux system, the cgroup hierarchy looks like this:

```
-.slice (Root Slice)
├── system.slice (System Services)
│   ├── sshd.service
│   ├── nginx.service
│   ├── postgresql.service
│   ├── systemd-logind.service
│   └── systemd-journald.service
├── user.slice (User Sessions)
│   ├── user-1000.slice
│   │   └── session-1.scope
│   └── user-1001.slice
└── machine.slice (Containers/VMs)
    ├── docker-abc123.scope
    └── libvirt-xyz789.scope
```

### Key Slices Explained

| Slice | Purpose | Contains |
|-------|---------|----------|
| **`-.slice`** | Root slice (top-level) | All other slices |
| **`system.slice`** | System services | Daemons, servers, system services |
| **`user.slice`** | User sessions | Login sessions, user processes |
| **`machine.slice`** | Virtual machines/containers | Docker, Podman, VMs |

---

## ⚙️ How `system.slice` Works

### 1. Default Home for Services

When you start a system service (e.g., via `systemctl start nginx`), systemd places it in `system.slice` by default.

```bash
# Check where a service lives
systemctl status nginx | grep -i cgroup

# Example output:
# CGroup: /system.slice/nginx.service
```

### 2. Resource Control

`system.slice` is a cgroup node where you can apply resource limits that affect **all services** inside it.

```bash
# Set CPU limit for all services in system.slice (global)
sudo systemctl set-property system.slice CPUQuota=80%

# Set memory limit for all services in system.slice
sudo systemctl set-property system.slice MemoryMax=4G
```

### 3. Creating Sub-slices

You can create custom slices under `system.slice` for finer control:

```bash
# Create a custom slice file
sudo tee /etc/systemd/system/myapp.slice <<'EOF'
[Slice]
CPUQuota=50%
MemoryMax=1G
EOF

# Reload systemd
sudo systemctl daemon-reload

# Run a service in the custom slice
sudo systemd-run --slice=myapp.slice --unit=myapp.service /usr/bin/myapp
```

The hierarchy becomes:

```
system.slice
└── myapp.slice
    └── myapp.service
```

## 🛠️ Common Operations

### Viewing the cgroup Hierarchy

```bash
# Show all cgroups in tree format
systemd-cgls

# Show only system.slice and its children
systemd-cgls system.slice

# Show all cgroups including their resource usage
systemd-cgtop
```

### Checking Resource Usage

```bash
# Monitor CPU and memory usage per cgroup
systemd-cgtop

# Check specific slice
systemd-cgtop system.slice
```

### Inspecting a Slice

```bash
# View slice properties
systemctl show system.slice

# View specific properties
systemctl show system.slice | grep -E "CPUQuota|MemoryMax"
```

### Setting Resource Limits

```bash
# Set CPU quota for the entire system.slice (global)
sudo systemctl set-property system.slice CPUQuota=80%

# Set memory limit
sudo systemctl set-property system.slice MemoryMax=4G

# Make limits persistent (survive reboot)
sudo systemctl set-property system.slice CPUQuota=80% --runtime=false
```

## 🎯 Why `system.slice` Matters

### 1. Resource Isolation

Without slices, all system services compete for resources without constraints:

```
No Slices (Chaotic):
┌─────────────────────────────────────────────────────────────┐
│                    Linux System                              │
│                                                             │
│   ┌─────────────────────────────────────────────────────┐   │
│   │  nginx (80% CPU) │ postgres (15% CPU) │ sshd (5%) │   │
│   └─────────────────────────────────────────────────────┘   │
│                                                             │
│   ❌ No isolation → One service can starve others         │
└─────────────────────────────────────────────────────────────┘

With system.slice (Organized):
┌─────────────────────────────────────────────────────────────┐
│                    Linux System                              │
│                                                             │
│   ┌─────────────────────────────────────────────────────┐   │
│   │                    system.slice                       │   │
│   │                    (CPU: 80%, Memory: 4G)            │   │
│   │                                                     │   │
│   │   ┌───────────┐  ┌───────────┐  ┌───────────┐    │   │
│   │   │  nginx    │  │ postgres  │  │   sshd    │    │   │
│   │   │  30% CPU  │  │  25% CPU  │  │   5% CPU  │    │   │
│   │   └───────────┘  └───────────┘  └───────────┘    │   │
│   └─────────────────────────────────────────────────────┘   │
│                                                             │
│   ✅ Services share the slice's allocated resources      │
└─────────────────────────────────────────────────────────────┘
```

### 2. Hierarchical Management

You can create sub-slices for different application tiers:

```
system.slice (80% CPU, 4G Memory)
├── web.slice (40% CPU, 2G Memory)
│   ├── nginx.service
│   ├── apache.service
│   └── haproxy.service
├── app.slice (30% CPU, 1.5G Memory)
│   ├── backend.service
│   └── worker.service
└── db.slice (10% CPU, 500M Memory)
    ├── postgresql.service
    └── redis.service
```

### 3. System Stability

```
Without system.slice:
┌─────────────────────────────────────────────────────────────┐
│                    Problem Scenario                          │
│                                                             │
│   1. Service A has a memory leak                           │
│   2. Service A consumes all memory                         │
│   3. Service B crashes due to OOM (Out-Of-Memory)         │
│   4. System becomes unstable → Manual intervention       │
│                                                             │
│   ❌ No isolation → One bad service affects all           │
└─────────────────────────────────────────────────────────────┘

With system.slice:
┌─────────────────────────────────────────────────────────────┐
│                    Protected Scenario                        │
│                                                             │
│   1. Service A has a memory leak                           │
│   2. Service A hits 500MB limit (set in its sub-slice)    │
│   3. Service A is OOM-killed                                │
│   4. Service B continues running unaffected               │
│                                                             │
│   ✅ Isolation → One bad service doesn't affect others    │
└─────────────────────────────────────────────────────────────┘
```

## 🔗 Relationship with Other Slices

### system.slice vs user.slice

| Aspect | system.slice | user.slice |
|--------|--------------|------------|
| **Purpose** | System services | User sessions |
| **Created By** | Systemd on boot | User login |
| **Contains** | Daemons, servers | Shells, user apps |
| **Example** | `nginx.service` | `session-1.scope` |
| **Resource Limits** | Set by admin | User-specific |

### system.slice vs machine.slice

| Aspect | system.slice | machine.slice |
|--------|--------------|---------------|
| **Purpose** | System services | Containers/VMs |
| **Contains** | Native services | Docker, Podman, VMs |
| **Example** | `sshd.service` | `docker-abc123.scope` |
| **Use Case** | Core system | Virtualization |

## 💡 Real-World Examples

### Example 1: Limiting All System Services

```bash
# Global limit for all system services
sudo systemctl set-property system.slice CPUQuota=80%
sudo systemctl set-property system.slice MemoryMax=4G

# Verify
systemctl show system.slice | grep -E "CPUQuota|MemoryMax"
```

### Example 2: Creating a Web Server Slice

```bash
# Create slice file
sudo tee /etc/systemd/system/web.slice <<'EOF'
[Slice]
CPUQuota=50%
MemoryMax=2G
EOF

# Reload
sudo systemctl daemon-reload

# Start services in the slice
sudo systemd-run --slice=web.slice --unit=nginx.service /usr/sbin/nginx
sudo systemd-run --slice=web.slice --unit=apache.service /usr/sbin/apache2

# Verify
systemd-cgls web.slice
```

### Example 3: Docker Containers in machine.slice

```bash
# Docker containers automatically go to machine.slice
docker run -d --name web --cpus=0.5 --memory=256m nginx

# Check where it lives
systemd-cgls machine.slice
```
