# 🔍 Understanding `docker-<container_id>.scope`

`docker-<container_id>.scope` is a **transient systemd scope unit** that Docker creates for each container when using the `systemd` cgroup driver. It appears as a directory node in the cgroup v2 hierarchy.

---

## 📊 What is `docker-<container_id>.scope`?

| Aspect | Description |
|--------|-------------|
| **Type** | Systemd transient scope unit |
| **Purpose** | Manages and limits container resources via cgroups |
| **Location** | `/sys/fs/cgroup/system.slice/docker-<container_id>.scope/` |
| **Created By** | Docker daemon (`dockerd`) via systemd |
| **Lifecycle** | Temporary — removed when container stops |

---

## 🔗 Where Does It Live?

In a cgroup v2 system with systemd as the cgroup manager:

```
/sys/fs/cgroup/
└── system.slice/
    ├── docker-abc123.scope/
    │   ├── cgroup.controllers
    │   ├── cgroup.procs
    │   ├── cpu.max
    │   ├── memory.max
    │   └── ...
    ├── docker-def456.scope/
    └── docker-ghi789.scope/
```

### How to Find Yours

```bash
# List all Docker container scopes
ls -l /sys/fs/cgroup/system.slice/ | grep docker

# Find a specific container
docker ps
CONTAINER ID   IMAGE     COMMAND   CREATED   STATUS
abc123...      nginx     ...       1m ago    Up 1m

# Check its cgroup
ls -l /sys/fs/cgroup/system.slice/ | grep abc123
# Output: drwxr-xr-x ... docker-abc123.scope/
```

## ⚙️ How It Works

### Step-by-Step Flow

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    Container Creation Flow                                  │
│                                                                             │
│   1. User runs: docker run --memory=512m --cpus=0.5 nginx                │
│                        ↓                                                    │
│   2. Docker daemon requests systemd to create a scope                     │
│                        ↓                                                    │
│   3. systemd creates: docker-<container_id>.scope                         │
│                        ↓                                                    │
│   4. systemd creates cgroup directory:                                    │
│      /sys/fs/cgroup/system.slice/docker-<container_id>.scope/             │
│                        ↓                                                    │
│   5. systemd writes limits to cgroup files:                               │
│      - memory.max = 512M                                                   │
│      - cpu.max = 50000 100000                                             │
│                        ↓                                                    │
│   6. Container PID is added to cgroup.procs                               │
│                        ↓                                                    │
│   7. Container runs with resource limits applied                          │
└─────────────────────────────────────────────────────────────────────────────┘
```

### How to Verify the Scope

```bash
# Check the scope unit
systemctl status docker-abc123.scope

# Example output:
● docker-abc123.scope - docker-abc123.scope
   Loaded: loaded (/run/systemd/transient/docker-abc123.scope; transient)
   Active: active (running) since ...
   CGroup: /system.slice/docker-abc123.scope
           └─12345 /usr/bin/nginx
```

## 🛠️ Viewing and Managing Scopes

### List All Docker Scopes

```bash
# Using systemd-cgls
systemd-cgls | grep docker

# Using systemctl
systemctl list-units --all | grep docker-.*.scope

# Direct filesystem
ls -la /sys/fs/cgroup/system.slice/ | grep docker
```

### Check Resource Limits

```bash
# Check memory limit
cat /sys/fs/cgroup/system.slice/docker-abc123.scope/memory.max

# Check CPU limit
cat /sys/fs/cgroup/system.slice/docker-abc123.scope/cpu.max

# Check all limits using systemd
systemctl show docker-abc123.scope | grep -E "MemoryMax|CPUQuota"
```

### Monitor Resource Usage

```bash
# Using systemd-cgtop
systemd-cgtop

# Using cgroup files
cat /sys/fs/cgroup/system.slice/docker-abc123.scope/memory.current
cat /sys/fs/cgroup/system.slice/docker-abc123.scope/cpu.stat
```

## 🔍 Deep Dive: Scope vs Slice vs Service

| Unit Type | Description | Example | Lifecycle |
|-----------|-------------|---------|-----------|
| **Slice** | Hierarchical container | `system.slice`, `user.slice` | Persistent |
| **Service** | Managed by systemd | `nginx.service`, `postgres.service` | Persistent |
| **Scope** | Transient unit for external processes | `docker-abc123.scope` | Temporary |

### Relationship

```
system.slice (Slice)
└── docker-abc123.scope (Scope)
    └── Container processes (PIDs)
```

## 🎯 Why Docker Uses Scopes

### Benefits of Scope Units

| Benefit | Explanation |
|---------|-------------|
| **Transient Management** | Scopes are automatically created/deleted with containers |
| **Resource Limits** | Systemd applies CPU, memory, I/O limits directly |
| **Integration** | Works seamlessly with systemd's cgroup management |
| **Cleanup** | No leftover cgroups when containers are removed |
| **Monitoring** | Use systemd tools (`systemd-cgtop`, `systemctl`) |

### Comparison: Scope vs Direct cgroupfs

| Method | Advantages | Disadvantages |
|--------|------------|---------------|
| **Direct cgroupfs** | Low-level control | Not persistent, manual cleanup needed |
| **Scope (systemd)** | Automatic management, cleanup, integration | Slightly more overhead |

## 📝 Common Commands Cheat Sheet

```bash
# List all Docker scopes
systemctl list-units --all | grep docker-.*.scope

# Show scope status
systemctl status docker-abc123.scope

# Show scope properties
systemctl show docker-abc123.scope

# Show CPU and memory limits
systemctl show docker-abc123.scope | grep -E "MemoryMax|CPUQuota"

# Direct cgroup files
cat /sys/fs/cgroup/system.slice/docker-abc123.scope/memory.max
cat /sys/fs/cgroup/system.slice/docker-abc123.scope/cpu.max

# Monitor resource usage
systemd-cgtop

# Stop and remove scope (cleaned up automatically when container stops)
docker stop abc123
```

## 💡 Best Practices

| Practice | Why |
|----------|-----|
| **Don't manually modify scope cgroups** | Systemd manages them; direct changes may be overwritten |
| **Use docker flags for limits** | `--memory`, `--cpus` are the correct way |
| **Monitor using systemd tools** | `systemd-cgtop` gives clear visibility |
| **Use systemd cgroup driver** | Recommended for cgroup v2 compatibility |
| **Clean up stopped containers** | Removes scopes automatically |
