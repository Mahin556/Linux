# 🔍 How Podman Manages cgroups (Rootful, Rootless, and Systemd Services)

Podman's approach to cgroups is fundamentally different from Docker's. It's **daemonless** and deeply integrates with `systemd`, especially for **rootless** operation. Here's a detailed breakdown.

---

## 📊 Podman's cgroup Manager Options

Podman can use one of two cgroup managers:

| Manager | Description | Default |
|---------|-------------|---------|
| **`systemd`** | Delegates cgroup management to systemd | ✅ Yes (recommended) |
| **`cgroupfs`** | Directly manipulates cgroup filesystem | ❌ No (fallback) |

```bash
# Check which manager Podman is using
podman info | grep -A 5 "cgroupManager"
```

---

## 👑 Mode 1: Rootful (System Mode) — `sudo podman`

When running as **root**, Podman behaves similarly to Docker.

### How It Works

1. **Podman Process** → Connects to the cgroup filesystem directly (or via systemd)
2. **Creates cgroup** → Under `/sys/fs/cgroup/system.slice/` or `/sys/fs/cgroup/machine.slice/`
3. **Applies Limits** → Writes to `cpu.max`, `memory.max`, etc.
4. **Adds PID** → Moves container's PID to `cgroup.procs`

### Example

```bash
# Run a container with memory limits
sudo podman run --memory=512m --cpus=0.5 nginx
```

### cgroup Location

With `systemd` manager (default):

```
/sys/fs/cgroup/system.slice/podman-<container_id>.scope/
```

Or with `cgroupfs` manager:

```
/sys/fs/cgroup/machine.slice/podman-<container_id>.scope/
```

### Verification

```bash
# Check the cgroup
sudo ls -l /sys/fs/cgroup/system.slice/ | grep podman

# Check limits
sudo cat /sys/fs/cgroup/system.slice/podman-<id>.scope/memory.max
```

## 👤 Mode 2: Rootless Mode — `podman` (No sudo)

This is Podman's **killer feature** and where cgroup handling gets interesting.

### Requirements for Rootless

| Requirement | Why |
|-------------|-----|
| **cgroups v2** | Rootless cgroups require the unified hierarchy |
| **systemd user session** | Needed for delegation and cgroup management |
| **User namespaces** | Provides root-like capabilities without actual root |
| **D-Bus user session** | Needed for systemd communication |

### How Rootless Podman Works

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    Rootless Podman Architecture                            │
│                                                                             │
│   ┌─────────────────────────────────────────────────────────────────────┐   │
│   │                    User Process (podman run)                        │   │
│   └─────────────────────────────────────────────────────────────────────┘   │
│                                    │                                        │
│                                    ▼                                        │
│   ┌─────────────────────────────────────────────────────────────────────┐   │
│   │                    User Namespace (UID 1000)                        │   │
│   │                    (Mapped to root UID 0 in container)             │   │
│   └─────────────────────────────────────────────────────────────────────┘   │
│                                    │                                        │
│                                    ▼                                        │
│   ┌─────────────────────────────────────────────────────────────────────┐   │
│   │                    systemd --user                                    │   │
│   │                    (User-level systemd instance)                    │   │
│   └─────────────────────────────────────────────────────────────────────┘   │
│                                    │                                        │
│                                    ▼                                        │
│   ┌─────────────────────────────────────────────────────────────────────┐   │
│   │                    /sys/fs/cgroup/user.slice/user-1000.slice/      │   │
│   │                    (Cgroup delegated to the user)                  │   │
│   └─────────────────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────────────────┘
```

### Rootless cgroup Location

For a user with UID 1000:

```
/sys/fs/cgroup/user.slice/user-1000.slice/user@1000.service/
├── user.slice/
│   └── podman-<container_id>.scope/
│       ├── cpu.max
│       ├── memory.max
│       └── cgroup.procs
```

### Resource Limitations in Rootless Mode

| Limitation | Why |
|------------|-----|
| **CPU limits may not work** | CPU controller delegation varies by distro |
| **Memory limits work partially** | Usually works for memory.max |
| **No `--cpus` on some systems** | Requires full CPU controller delegation |
| **I/O limits limited** | IO controller delegation is restricted |

### Example

```bash
# Try to limit memory (usually works)
podman run --memory=512m nginx

# Try to limit CPU (may not work on all systems)
podman run --cpus=0.5 nginx

# Check if limits applied
podman inspect <container> | grep -A 5 "CgroupParent"
```

### Enable CPU Limits for Rootless (if not working)

```bash
# Enable CPU controller delegation (requires root)
sudo mkdir -p /etc/systemd/system/user@.service.d/
sudo tee /etc/systemd/system/user@.service.d/delegate.conf <<'EOF'
[Service]
Delegate=cpu cpuset io memory pids
EOF

sudo systemctl daemon-reload
sudo systemctl restart user@$(id -u).service
```

## 🧩 Mode 3: Creating Systemd Services for Podman Containers

When you create a **systemd service** that runs a Podman container, the cgroup hierarchy becomes more complex.

### How It Works

```
/sys/fs/cgroup/
└── system.slice/
    └── <your-service>.service/        ← Systemd service itself
        └── machine.slice/              ← Podman machine slice
            └── libpod-payload.scope/   ← Container scope (old)
                └── ... cgroup files
```

### Creating a Systemd Service for a Container

```bash
# Generate a systemd service file for a rootful container
sudo podman generate systemd --name mycontainer --new > /etc/systemd/system/mycontainer.service

# For rootless
podman generate systemd --name mycontainer --new > ~/.config/systemd/user/mycontainer.service
```

### Service File Example

```ini
[Unit]
Description=My Podman Container
Requires=network-online.target
After=network-online.target

[Service]
Type=forking
ExecStartPre=/bin/rm -f %t/%n.ctr-id
ExecStart=/usr/bin/podman run --cgroups=no-conmon -d --conmon-pidfile %t/%n.pid --cidfile %t/%n.ctr-id --name mycontainer nginx
ExecStop=/usr/bin/podman stop --cidfile %t/%n.ctr-id -t 10
ExecStopPost=/usr/bin/podman rm --cidfile %t/%n.ctr-id -f

[Install]
WantedBy=multi-user.target
```

### cgroup Hierarchy for Systemd Service

```
system.slice/
└── mycontainer.service/
    └── machine.slice/
        └── libpod-<container_id>.scope/
            └── (container processes)
```

### Verify the Service's cgroup

```bash
# Check service status
systemctl status mycontainer.service

# Check cgroup location
systemd-cgls | grep -A 5 "mycontainer.service"

# Check resource limits
sudo cat /sys/fs/cgroup/system.slice/mycontainer.service/cpu.max
sudo cat /sys/fs/cgroup/system.slice/mycontainer.service/memory.max
```

## 📊 Comparison: Rootful vs Rootless vs Systemd Service

| Aspect | Rootful (sudo) | Rootless | Systemd Service (Rootful) |
|--------|---------------|----------|---------------------------|
| **Cgroup Manager** | systemd (default) | systemd --user | systemd (system) |
| **Location** | `/sys/fs/cgroup/system.slice/` | `/sys/fs/cgroup/user.slice/user-<UID>.slice/` | `/sys/fs/cgroup/system.slice/<service>.service/` |
| **CPU Limits** | ✅ Full support | ⚠️ Limited | ✅ Full support |
| **Memory Limits** | ✅ Full support | ✅ Usually works | ✅ Full support |
| **I/O Limits** | ✅ Full support | ⚠️ Limited | ✅ Full support |
| **Auto-start** | N/A | N/A | ✅ Yes |
| **Cleanup** | Auto on exit | Auto on exit | Managed by systemd |
| **Cgroup Subtree** | `machine.slice` | `user.slice` | `machine.slice` under service |

## 🔧 Common Commands

### View cgroup Hierarchy

```bash
# Rootful
sudo systemd-cgls

# Rootless
systemd-cgls --user

# View specific service
systemd-cgls mycontainer.service
```

### Check Resource Usage

```bash
# Using systemd-cgtop
systemd-cgtop

# Using cgroup files
cat /sys/fs/cgroup/system.slice/mycontainer.service/memory.current
cat /sys/fs/cgroup/system.slice/mycontainer.service/cpu.stat
```

### Check cgroup Manager

```bash
# Check Podman's cgroup configuration
podman info | grep -A 5 "cgroupManager"
```

---

## 🏁 Summary

| Mode | cgroup Manager | Limitations | Best For |
|------|---------------|-------------|----------|
| **Rootful** | systemd | None | Production, privileged workloads |
| **Rootless** | systemd --user | CPU limits may not work, I/O limits limited | Development, CI/CD, unprivileged users |
| **Systemd Service (Rootful)** | systemd | None | Permanent containers, auto-start at boot |
| **Systemd Service (Rootless)** | systemd --user | Same as rootless | Permanent rootless containers |
