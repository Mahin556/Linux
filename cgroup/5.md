# 🎯 Setting CPU and Memory Limits for a Specific Service

There are several ways to set CPU and memory limits for a **specific service** instead of an entire slice. Here's a comprehensive guide to each method.

---

## 📋 Method 1: Using `systemctl set-property` (Runtime & Persistent)

This is the quickest way to set limits on a running service.

### Basic Syntax

```bash
sudo systemctl set-property <service-name> CPUQuota=<value> MemoryMax=<value>
```

### Examples

```bash
# Limit a service to 50% CPU and 500MB memory
sudo systemctl set-property nginx.service CPUQuota=50% MemoryMax=500M

# Limit a service to 200% CPU (2 cores) and 2GB memory
sudo systemctl set-property postgresql.service CPUQuota=200% MemoryMax=2G

# Limit to 25% CPU and 128MB memory
sudo systemctl set-property redis.service CPUQuota=25% MemoryMax=128M
```

### Verify the Limits

```bash
# Check properties
systemctl show nginx.service | grep -E "CPUQuota|MemoryMax"

# Check cgroup
systemd-cgls system.slice/nginx.service
```

### Make Limits Persistent (Survive Reboot)

```bash
# Apply with --runtime=false (default is true)
sudo systemctl set-property nginx.service CPUQuota=50% --runtime=false
sudo systemctl set-property nginx.service MemoryMax=500M --runtime=false
```

### Remove Limits

```bash
# Set to infinite values
sudo systemctl set-property nginx.service CPUQuota=100% MemoryMax=infinity
```

## 📋 Method 2: Editing the Service Unit File (Persistent)

This method makes limits permanent and survives reboots.

### Step 1: Locate the Service File

```bash
# Find the service file location
systemctl show nginx.service | grep -i "FragmentPath"

# Example output:
# FragmentPath=/lib/systemd/system/nginx.service
```

### Step 2: Create Override Directory

```bash
# Create override directory
sudo mkdir -p /etc/systemd/system/nginx.service.d/

# Create override file
sudo tee /etc/systemd/system/nginx.service.d/override.conf <<'EOF'
[Service]
CPUQuota=50%
MemoryMax=500M
EOF
```

### Step 3: Reload and Restart

```bash
# Reload systemd
sudo systemctl daemon-reload

# Restart the service
sudo systemctl restart nginx.service

# Verify
systemctl show nginx.service | grep -E "CPUQuota|MemoryMax"
```

### Step 4: Remove Override (If Needed)

```bash
sudo rm -rf /etc/systemd/system/nginx.service.d/
sudo systemctl daemon-reload
sudo systemctl restart nginx.service
```

## 📋 Method 3: Using `systemd-run` (Transient Service)

This creates a temporary service with limits.

### Basic Syntax

```bash
sudo systemd-run -u <service-name> -p CPUQuota=<value> -p MemoryMax=<value> <command>
```

### Examples

```bash
# Run a one-time command with limits
sudo systemd-run -u my-hog -p CPUQuota=50% -p MemoryMax=500M /usr/bin/hog

# Run a service with limits
sudo systemd-run -u custom-app -p CPUQuota=30% -p MemoryMax=256M /usr/bin/my-app

# Run with 2 cores and 1GB memory
sudo systemd-run -u data-processor -p CPUQuota=200% -p MemoryMax=1G /usr/bin/data-process
```

### Check the Service

```bash
# Check status
systemctl status my-hog.service

# Check cgroup
systemd-cgls | grep my-hog

# Check limits
systemctl show my-hog.service | grep -E "CPUQuota|MemoryMax"
```

### Stop and Clean Up

```bash
# Stop the transient service
sudo systemctl stop my-hog.service

# Reset failed units
sudo systemctl reset-failed
```

## 📋 Method 4: Using `cgset` (Manual cgroup)

This method manually sets limits on a service's cgroup.

### Step 1: Find the Service's Cgroup

```bash
# Find the cgroup path for the service
systemctl show nginx.service | grep -i cgroup

# Example output:
# ControlGroup=/system.slice/nginx.service

# The cgroup is at: /sys/fs/cgroup/system.slice/nginx.service/
```

### Step 2: Set Limits Using cgset

```bash
# Install cgroup-tools if needed
sudo apt-get install cgroup-tools  # Debian/Ubuntu

# Set CPU limit
sudo cgset -r cpu.max="50000 100000" system.slice/nginx.service

# Set memory limit
sudo cgset -r memory.max="500M" system.slice/nginx.service
```

### Step 3: Verify

```bash
# Check CPU limit
cgget -r cpu.max system.slice/nginx.service

# Check memory limit
cgget -r memory.max system.slice/nginx.service
```

---

## 📋 Method 5: Using Direct cgroupfs Write

This is the most manual method, writing directly to the filesystem.

### Step 1: Find the Service's Cgroup

```bash
# Find the cgroup path
ls -l /sys/fs/cgroup/system.slice/ | grep nginx

# Example: /sys/fs/cgroup/system.slice/nginx.service/
```

### Step 2: Set CPU Limit

```bash
# Check if cpu controller is enabled
cat /sys/fs/cgroup/system.slice/nginx.service/cgroup.controllers

# Set CPU limit (50% of one core)
echo "50000 100000" | sudo tee /sys/fs/cgroup/system.slice/nginx.service/cpu.max
```

### Step 3: Set Memory Limit

```bash
# Set memory limit
echo "500M" | sudo tee /sys/fs/cgroup/system.slice/nginx.service/memory.max
```

### Step 4: Verify

```bash
# Check CPU limit
cat /sys/fs/cgroup/system.slice/nginx.service/cpu.max

# Check memory limit
cat /sys/fs/cgroup/system.slice/nginx.service/memory.max
```

## 📊 Comparison Table

| Method | Persistent | Runtime | Complexity | Best For |
|--------|------------|---------|------------|----------|
| **systemctl set-property** | ✅ Yes (with flag) | ✅ Yes | Low | Quick changes, testing |
| **Service Unit Override** | ✅ Yes | ✅ Yes | Medium | Permanent configurations |
| **systemd-run** | ❌ No | ✅ Yes | Low | Temporary services |
| **cgset** | ❌ No | ✅ Yes | Medium | Scripting, bulk changes |
| **Direct cgroupfs** | ❌ No | ✅ Yes | High | Debugging, low-level control |

## 🎯 Examples for Common Services

### Web Server (Nginx)

```bash
# Method 1: Quick runtime limit
sudo systemctl set-property nginx.service CPUQuota=50% MemoryMax=500M

# Method 2: Permanent limit
sudo mkdir -p /etc/systemd/system/nginx.service.d/
sudo tee /etc/systemd/system/nginx.service.d/override.conf <<'EOF'
[Service]
CPUQuota=50%
MemoryMax=500M
EOF
sudo systemctl daemon-reload
sudo systemctl restart nginx.service
```

### Database (PostgreSQL)

```bash
# Limit to 80% CPU and 4GB memory
sudo systemctl set-property postgresql.service CPUQuota=80% MemoryMax=4G
```

### Cache (Redis)

```bash
# Limit to 25% CPU and 1GB memory
sudo systemctl set-property redis.service CPUQuota=25% MemoryMax=1G
```

### Custom Application

```bash
# Run a custom app with limits
sudo systemd-run -u myapp -p CPUQuota=30% -p MemoryMax=256M /opt/myapp/bin/start.sh
```

## 💡 Best Practices

| Practice | Why |
|----------|-----|
| **Use service overrides for permanent changes** | Survives reboots, easy to manage |
| **Use set-property for testing** | Quick changes without editing files |
| **Start with conservative limits** | Avoid starving the service |
| **Monitor resource usage first** | Understand baseline before limiting |
| **Document your limits** | Team awareness |
