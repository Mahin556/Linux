# 📖 Understanding systemd.slice — Complete Guide

`systemd.slice` is a unit type in systemd that organizes processes into a hierarchical tree for resource management using Linux Control Groups (cgroups). This guide explains everything you need to know about slice units.

---

## 📚 What is a Slice Unit?

A **slice unit** (file ending in `.slice`) is a systemd concept for **hierarchically managing resources** of a group of processes.

| Aspect | Description |
|--------|-------------|
| **Purpose** | Organize processes into a tree structure for resource management |
| **Implementation** | Creates a node in the Linux cgroup tree |
| **Scope** | Contains service and scope units |
| **Resource Limits** | Limits applied to a slice affect all units within it |

---

## 🏗️ Slice Hierarchy and Naming

### Naming Convention

The name of a slice encodes its position in the tree:

```
-.slice (Root Slice)
├── system.slice
│   ├── sshd.service
│   └── nginx.service
├── user.slice
│   └── user-1000.slice
└── machine.slice
    └── docker-abc123.scope
```

### Name Structure

```
foo-bar.slice
    ↓
Located within foo.slice
    ↓
Which is located within the root slice (-.slice)
```

| Slice Name | Location in Hierarchy |
|------------|----------------------|
| `-.slice` | Root slice (top-level) |
| `foo.slice` | Direct child of root |
| `foo-bar.slice` | Child of `foo.slice` |
| `foo-bar-baz.slice` | Child of `foo-bar.slice` |

### Default Slices

| Slice | Purpose |
|-------|---------|
| **`-.slice`** | Root slice |
| **`system.slice`** | System services (default for services) |
| **`user.slice`** | User sessions (handled by systemd-logind) |
| **`machine.slice`** | Virtual machines and containers (handled by systemd-machined) |

## ⚙️ Automatic Dependencies

### Implicit Dependencies

Slice units automatically get:

| Dependency | Purpose |
|------------|---------|
| **`After=`** | Slice starts after its parent slice |
| **`Requires=`** | Slice requires its parent slice |

### Default Dependencies

Unless `DefaultDependencies=no` is set:

| Dependency | Purpose |
|------------|---------|
| **`Conflicts=shutdown.target`** | Slice is stopped during shutdown |
| **`Before=shutdown.target`** | Slice stops before shutdown |

## 🔧 Slice Configuration Options

### [Unit] Section

Standard unit options (see `systemd.unit(5)`):
- `Description=`
- `Documentation=`
- `Wants=`
- `Requires=`
- `After=`
- `Before=`

### [Slice] Section

| Option | Description | Default |
|--------|-------------|---------|
| **`ConcurrencyHardMax=`** | Hard limit on concurrent active units in slice | `infinity` |
| **`ConcurrencySoftMax=`** | Soft limit (queues activations when reached) | `infinity` |

### Resource Control Options

All options from `systemd.resource-control(5)` are available:

| Option | Description | Example |
|--------|-------------|---------|
| **`CPUQuota=`** | CPU time limit | `CPUQuota=50%` |
| **`MemoryMax=`** | Memory limit | `MemoryMax=1G` |
| **`MemoryHigh=`** | Memory high watermark | `MemoryHigh=800M` |
| **`TasksMax=`** | Maximum number of tasks | `TasksMax=100` |
| **`IOWeight=`** | I/O priority weight | `IOWeight=100` |

## 📝 Example Slice Configuration

### Creating a Custom Slice

```bash
# Create slice file
sudo tee /etc/systemd/system/myapp.slice <<'EOF'
[Unit]
Description=My Application Slice
Documentation=https://example.com/docs
After=system.slice

[Slice]
CPUQuota=50%
MemoryMax=2G
MemoryHigh=1.5G
TasksMax=50
ConcurrencyHardMax=10
ConcurrencySoftMax=5

[Install]
WantedBy=multi-user.target
EOF

# Reload systemd
sudo systemctl daemon-reload

# Start the slice
sudo systemctl start myapp.slice

# Enable to start at boot
sudo systemctl enable myapp.slice
```

### Running Services in the Slice

```bash
# Method 1: Using systemd-run
sudo systemd-run --slice=myapp.slice --unit=app1.service /usr/bin/myapp

# Method 2: Using service unit file
sudo tee /etc/systemd/system/app1.service <<'EOF'
[Unit]
Description=App 1

[Service]
Slice=myapp.slice
ExecStart=/usr/bin/myapp

[Install]
WantedBy=multi-user.target
EOF

# Method 3: Using systemctl set-property
sudo systemctl set-property myapp.slice CPUQuota=50% MemoryMax=2G
```

## 🔍 Concurrency Limits

### ConcurrencyHardMax

```ini
[Slice]
ConcurrencyHardMax=5
```

| Effect | Description |
|--------|-------------|
| **When reached** | No further units can be activated |
| **Result** | Activation fails with an error |
| **Counting** | Includes both payload units (services) AND structural units (sub-slices) |

### ConcurrencySoftMax

```ini
[Slice]
ConcurrencySoftMax=3
```

| Effect | Description |
|--------|-------------|
| **When reached** | Further activations are queued |
| **Result** | No immediate error; jobs wait |
| **Processing** | Jobs processed when concurrency drops below limit |

### Processing Order

When multiple start jobs are queued:

1. **Unit type** (services first, then mounts, etc.)
2. **CPU weight** (higher weight = higher priority)
3. **Nice level** (lower nice = higher priority)
4. **Alphabetical order** (by unit name)

## 🧩 Hierarchical Resource Control

### How Limits Propagate

```
-.slice
├── system.slice (CPU: 80%, Memory: 4G)
│   ├── web.slice (CPU: 50%, Memory: 2G)
│   │   ├── nginx.service
│   │   └── apache.service
│   ├── db.slice (CPU: 30%, Memory: 1.5G)
│   │   └── postgresql.service
│   └── app.slice (CPU: 20%, Memory: 500M)
│       └── myapp.service
└── user.slice (CPU: 20%, Memory: 2G)
```

### Inheritance Rules

| Rule | Description |
|------|-------------|
| **Child inherits parent limits** | Slices cannot exceed parent limits |
| **Sub-slices count as units** | Each slice counts toward concurrency limits |
| **Limits are hierarchical** | Limits apply to all descendants |

## 🛠️ Common Operations

### Viewing Slices

```bash
# Show all slices
systemd-cgls

# Show specific slice
systemd-cgls system.slice

# Show slice properties
systemctl show system.slice

# Show slice status
systemctl status system.slice
```

### Modifying Slice Properties

```bash
# Set CPU limit
sudo systemctl set-property system.slice CPUQuota=80%

# Set memory limit
sudo systemctl set-property system.slice MemoryMax=4G

# Make persistent
sudo systemctl set-property system.slice CPUQuota=80% --runtime=false

# Remove limit
sudo systemctl set-property system.slice MemoryMax=infinity
```

### Creating Sub-slices

```bash
# Create sub-slice directory
sudo mkdir -p /etc/systemd/system/web.slice

# Create sub-slice file
sudo tee /etc/systemd/system/web.slice <<'EOF'
[Slice]
CPUQuota=50%
MemoryMax=2G
EOF

# Reload and start
sudo systemctl daemon-reload
sudo systemctl start web.slice
```

### Moving Services Between Slices

```bash
# Move a service to a different slice
sudo systemctl set-property nginx.service Slice=web.slice

# Override file method
sudo mkdir -p /etc/systemd/system/nginx.service.d/
sudo tee /etc/systemd/system/nginx.service.d/slice.conf <<'EOF'
[Service]
Slice=web.slice
EOF
sudo systemctl daemon-reload
sudo systemctl restart nginx.service
```

## 📊 Monitoring Resource Usage

### Using systemd-cgtop

```bash
# Show top cgroups by resource usage
systemd-cgtop

# Show specific slice
systemd-cgtop system.slice
```

### Using cgroup Files

```bash
# Memory usage
cat /sys/fs/cgroup/system.slice/web.slice/memory.current

# CPU usage
cat /sys/fs/cgroup/system.slice/web.slice/cpu.stat

# Memory limit
cat /sys/fs/cgroup/system.slice/web.slice/memory.max

# CPU limit
cat /sys/fs/cgroup/system.slice/web.slice/cpu.max
```

## 💡 Best Practices

| Practice | Why |
|----------|-----|
| **Use meaningful slice names** | Easy identification and management |
| **Set reasonable limits** | Avoid starving critical services |
| **Test limits in staging** | Verify before production |
| **Monitor resource usage** | Adjust limits based on actual usage |
| **Document your hierarchy** | Team awareness |
| **Use concurrency limits** | Prevent overloading the slice |
